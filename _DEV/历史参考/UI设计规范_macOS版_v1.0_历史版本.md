# 第一部分 UI 设计规范

## 1. 设计总原则

本软件为**临床决策支持工具**，核心用户是门诊医生。界面设计的最高目标是：**让医生在最短时间内、无歧义地理解当前临床状态和下一步操作**。

遵循以下四条原则，优先级从高到低：

1. **逻辑清晰优先于美观**：功能分区必须一目了然，任何装饰不得干扰信息阅读。医生的操作路径（预评估 → 完整评估 → 阶段复评 → 观察 → 判定 → 复评）必须始终可见。
2. **材质隐喻，克制的毛玻璃**：复刻 macOS 26 Liquid Glass 的"液态玻璃"质感，但透明度和模糊度控制在"提升层次感、不干扰文字"的范围内。禁止大面积高透明玻璃造成文字对比度下降。
3. **减少歧义**：每个按钮、标签、状态提示的文字必须明确表达"点击后会发生什么"。禁止使用"确定""提交"等含糊措辞，改用"进入完整评估""确认进入缓解观察期"等动词短语。
4. **减少不必要元素**：一个界面只呈现当前决策所需的元素。非当前步骤的字段、按钮、提示一律隐藏或折叠，禁止堆砌。

## 2. Design Token（AI 照抄）

> 以下数值是**强制约束**。AI 生成样式时必须使用下列 CSS 变量，禁止自行发明新颜色、新圆角、新间距。若确需新增，必须在 `mapping.md` 登记并经 Lifan 确认。

### 2.1 颜色色板

```css
:root {
  /* ===== 背景层 ===== */
  --bg-window:          #F5F5F7;   /* 窗口主背景（苹果浅灰） */
  --bg-sidebar:         #ECECEF;   /* 侧边导航栏背景 */
  --bg-content:         #FFFFFF;   /* 内容卡片/面板背景 */

  /* ===== 表面层（玻璃材质）===== */
  --surface-glass:      rgba(255, 255, 255, 0.72);  /* 玻璃面板主色 */
  --surface-glass-strong: rgba(255, 255, 255, 0.88); /* 强玻璃（模态框）*/
  --surface-fill:       #FFFFFF;   /* 非玻璃纯色填充 */

  /* ===== 文字层（三级）===== */
  --text-primary:       #1D1D1F;   /* 主文字：标题、关键结论 */
  --text-secondary:     #6E6E73;   /* 次文字：说明、辅助信息 */
  --text-tertiary:      #A1A1A6;   /* 弱文字：占位符、禁用态 */

  /* ===== 分割线与描边 ===== */
  --divider:            #E5E5EA;   /* 常规分割线 */
  --divider-strong:     #D2D2D7;   /* 强调分割线 */
  --stroke:             rgba(0, 0, 0, 0.10);  /* 玻璃描边（半透明）*/
  --stroke-strong:      rgba(0, 0, 0, 0.16);  /* 强调描边 */

  /* ===== 强调色（品牌蓝，苹果蓝）===== */
  --accent:             #007AFF;   /* 主强调色：按钮、链接、选中态 */
  --accent-hover:       #0066D6;   /* 悬停 */
  --accent-pressed:     #005BBF;   /* 按下 */
  --accent-tint:        rgba(0, 122, 255, 0.12); /* 强调色淡底（选中背景）*/

  /* ===== 语义色 ===== */
  --success:            #34C759;   /* 成功/达标（如"满足缓解条件"）*/
  --success-tint:       rgba(52, 199, 89, 0.12);
  --warning:            #FF9500;   /* 警告/暂缓（如"暂缓进入"）*/
  --warning-tint:       rgba(255, 149, 0, 0.12);
  --danger:             #FF3B30;   /* 危险/风险（如"急性不安全"）*/
  --danger-tint:        rgba(255, 59, 48, 0.12);

  /* ===== 玻璃高光 ===== */
  --glass-highlight:    rgba(255, 255, 255, 0.55); /* 玻璃顶部高光 */
}
```

**使用规则**：
- 主文字一律用 `--text-primary`；说明性文字用 `--text-secondary`；占位符/禁用用 `--text-tertiary`。禁止在正文使用灰色以外的不一致色。
- 强调色 `--accent` **仅**用于：主行动按钮、当前选中导航项、可点击链接。禁止大面积铺强调色。
- 语义色 `--success/--warning/--danger` **仅**用于临床状态标签，不得用于普通装饰。

### 2.2 圆角（Radius）

```css
:root {
  --radius-xs:   8px;   /* 小元素：标签、输入框内部 */
  --radius-sm:   12px;  /* 标准元素：按钮、输入框、下拉框 */
  --radius-md:   16px;  /* 卡片、面板 */
  --radius-lg:   20px;  /* 大型面板、模态框 */
  --radius-full: 999px; /* 胶囊：状态徽章、开关 */
}
```

**使用规则**：圆角是 macOS 26 玻璃质感的关键，**禁止使用直角（0px）**。层级越高（越"浮起"），圆角越大。

### 2.3 间距阶梯（Spacing）

```css
:root {
  --space-1:  4px;   /* 元素内部紧贴 */
  --space-2:  8px;   /* 相关元素之间 */
  --space-3:  12px;  /* 控件之间 */
  --space-4:  16px;  /* 区块内部留白 */
  --space-5:  24px;  /* 区块之间 */
  --space-6:  32px;  /* 大区块之间 */
  --space-7:  40px;  /* 页面级留白 */
}
```

**使用规则**：间距只允许取上表 7 个值，禁止出现 7px、13px、22px 等非阶梯值。使用 8 的倍数体系，保证视觉节奏一致。

### 2.4 字体栈与字号

```css
:root {
  --font-family: -apple-system, BlinkMacSystemFont, "SF Pro Text",
                 "PingFang SC", "Helvetica Neue", "Microsoft YaHei",
                 sans-serif;

  --font-size-caption: 12px;  /* 辅助标注 */
  --font-size-body:    14px;  /* 正文、表单项 */
  --font-size-subhead: 16px;  /* 小节标题、按钮 */
  --font-size-title:   20px;  /* 卡片标题 */
  --font-size-large:   28px;  /* 页面主标题 */

  --font-weight-regular: 400;
  --font-weight-medium:  500;
  --font-weight-semibold: 600;
  --font-weight-bold:    700;

  --line-height-tight:   1.3;
  --line-height-normal:  1.5;
}
```

**使用规则**：
- 正文默认 `--font-size-body`（14px），这是临床信息密集场景的最佳阅读字号，禁止随意放大正文。
- 关键临床结论（如"满足缓解条件"）可用 `--font-size-title` + `--font-weight-semibold` 强调，但同一界面最多出现**一处**大字号强调。
- 数字（如 HbA1c 6.5%）使用等宽数字特性 `font-variant-numeric: tabular-nums`，保证对齐。

### 2.5 毛玻璃参数（Liquid Glass）

```css
/* 玻璃面板标准参数 */
.glass-panel {
  background: var(--surface-glass);
  backdrop-filter: blur(20px) saturate(180%);
  -webkit-backdrop-filter: blur(20px) saturate(180%);
  border: 1px solid var(--stroke);
  box-shadow: 0 8px 24px rgba(0, 0, 0, 0.08);
}

/* 强玻璃（模态框、弹出层）*/
.glass-strong {
  background: var(--surface-glass-strong);
  backdrop-filter: blur(32px) saturate(200%);
  -webkit-backdrop-filter: blur(32px) saturate(200%);
  border: 1px solid var(--stroke-strong);
  box-shadow: 0 16px 48px rgba(0, 0, 0, 0.12);
}
```

**使用规则**：
- 玻璃面板 `blur(20px)`、模态框 `blur(32px)`，这是**固定值**，禁止自行调整。
- 玻璃只用于"浮起"层（面板、卡片、模态框），**正文内容区用纯色 `--bg-content`**，保证文字清晰度。
- 若浏览器不支持 `backdrop-filter`，降级为纯色 `--surface-fill` 并保留描边。

### 2.6 阴影与描边

```css
:root {
  --shadow-sm: 0 2px 8px  rgba(0, 0, 0, 0.04);  /* 轻微浮起：卡片 */
  --shadow-md: 0 8px 24px rgba(0, 0, 0, 0.08);  /* 标准浮起：玻璃面板 */
  --shadow-lg: 0 16px 48px rgba(0, 0, 0, 0.12); /* 强浮起：模态框 */

  --border-width: 1px;   /* 所有描边统一 1px */
}
```

**使用规则**：阴影只用于表达"浮起层级"，禁止给普通文字或静态区块加阴影。描边统一 1px 半透明，禁止 2px 以上的粗描边（除非是焦点环）。

## 3. 组件规范

### 3.1 按钮

| 层级 | 样式 | 用途 | 示例文案 |
|------|------|------|---------|
| 主按钮 | 强调色填充 `--accent`，白字，圆角 `--radius-sm` | 当前步骤**唯一**的主要行动 | "进入完整评估" |
| 次按钮 | 玻璃面板 + 描边，主文字色 | 次要行动、多选场景 | "暂缓进入" |
| 文字按钮 | 无背景，强调色文字 | 低干扰的辅助操作 | "查看历史记录" |
| 危险按钮 | `--danger` 填充，白字 | 不可逆或高风险操作 | （本项目很少用，慎用）|

**规则**：
- 一个界面最多**一个主按钮**。多个并列操作一律用次按钮。
- 按钮文字必须为**动词短语**，说明点击后果，禁止"确定""提交""是/否"。
- 主按钮高度统一 36px，次按钮 32px，内边距 12px 16px。

### 3.2 输入框

```css
.input {
  height: 36px;
  border: 1px solid var(--divider-strong);
  border-radius: var(--radius-sm);
  background: var(--surface-fill);
  padding: 0 var(--space-4);
  font-size: var(--font-size-body);
}
.input:focus {
  border-color: var(--accent);
  box-shadow: 0 0 0 3px var(--accent-tint);
}
```

**规则**：聚焦时显示强调色焦点环（3px 淡底），这是无障碍要求，禁止省略。

### 3.3 状态标签（临床结论徽章）

| 状态 | 背景 | 文字色 | 示例 |
|------|------|--------|------|
| 达标/成功 | `--success-tint` | `--success` | "满足缓解条件" |
| 暂缓/警告 | `--warning-tint` | `--warning` | "暂缓进入" |
| 风险/危险 | `--danger-tint` | `--danger` | "急性不安全" |
| 中性/进行中 | `--accent-tint` | `--accent` | "缓解观察期" |

**规则**：标签用胶囊形（`--radius-full`），内边距 2px 10px，字号 `--font-size-caption`。状态标签**只表达临床状态**，不用作装饰。

### 3.4 卡片与面板

- 内容卡片：纯色 `--bg-content`，圆角 `--radius-md`，1px 描边 `--divider`，阴影 `--shadow-sm`。
- 玻璃面板（浮起层）：`.glass-panel` 类，用于侧边栏、模态框、下拉菜单。
- 卡片内部标题用 `--font-size-subhead` + `--font-weight-semibold`，与内容区用 `--space-4` 间隔。

## 4. 布局规范

### 4.1 总体布局：三栏结构

```
┌─────────────┬──────────────────────────────────────┐
│             │  顶部导航（当前患者 + 流程进度指示）      │
│  侧边导航    ├──────────────────────────────────────┤
│  （6个流程   │                                      │
│   单元入口） │        内容区（当前步骤的决策表单）       │
│             │                                      │
│             ├──────────────────────────────────────┤
│             │  底部操作区（主按钮 + 次按钮）            │
└─────────────┴──────────────────────────────────────┘
```

- **侧边导航**（宽 220px，背景 `--bg-sidebar`）：列出 6 个流程单元（预评估/完整评估/阶段复评/观察期/缓解判定/缓解后复评），当前单元高亮（`--accent-tint` 背景 + `--accent` 文字），已完成单元显示对勾，未到单元置灰禁用。这是"功能分区一目了然"的核心。
- **顶部导航**：显示当前患者姓名/ID + 流程进度指示器（TimelineIndicator），让医生始终知道"在哪一步"。
- **内容区**：只呈现当前步骤的决策元素，滚动区域内置。
- **底部操作区**：固定主/次按钮，逻辑上"下一步去哪"一目了然。

### 4.2 流程进度指示器

用横向步骤条显示 6 个流程单元，当前步骤高亮，已完成打勾，未完成置灰。这是医生理解全局路径的关键，禁止省略。

### 4.3 响应式

- 最小支持宽度 1024px（门诊台式机/笔记本）。低于此宽度时侧边栏折叠为图标模式。
- 本项目不面向手机端，无需移动端适配。

## 5. 反模式清单（AI 禁止）

AI 生成界面时，以下行为**一律禁止**：

1. ❌ **禁止自定义非 Token 的颜色/圆角/间距**：必须使用第 2 节的 CSS 变量，不得硬编码 `#123456`、`border-radius: 7px`、`margin: 13px` 等。
2. ❌ **禁止使用"确定/提交/是/否"等含糊按钮文字**：必须说明动作后果。
3. ❌ **禁止大面积高透明玻璃**：玻璃只用于浮起层，正文区必须纯色。
4. ❌ **禁止堆砌非当前步骤的字段**：跨步骤字段应自动带入（如患者基本信息），不得重复展示/重复录入。
5. ❌ **禁止使用纯装饰性图标或无意义的动画**：每个图标、动效必须有明确功能含义。
6. ❌ **禁止中文界面混入英文标签**（除非是医学专业缩写如 HbA1c、BMI、FPG、CGM 等，这些保留英文）。
7. ❌ **禁止同一界面出现两个以上主按钮**。
8. ❌ **禁止将状态标签用于装饰**：颜色语义必须与临床状态严格对应。

# 第二部分 代码注释规范

## 6. 注释总原则

1. **简体中文优先**：所有注释一律使用简体中文。医学专业术语（HbA1c、BMI、FPG、CGM、SGLT2 等）和代码标识符（变量名、函数名）保留英文，但解释性文字用中文。
2. **每个文件、每个函数必须有块注释**：无块注释的代码视为未完成，禁止提交。
3. **重要步骤逐行注释**：涉及临床分支判断、状态转换、日期计算、数据持久化的代码，必须逐行说明"为什么这样做"。
4. **注释解释"为什么"，不解释"是什么"**：`x = x + 1` 这种自明代码不写 `# x 加 1`，而应写 `# 计数增加 1`——更关键的是说明业务含义。

## 10. 注释禁用项

1. ❌ **禁止英文注释**：注释文字必须中文（医学缩写除外）。
2. ❌ **禁止 TODO 无主**：`# TODO: 以后修` 这种无责任人、无期限的 TODO 禁止出现；如确需标记，格式为 `# TODO(Lifan): 2026-08-30 前补充 C肽缺失的分支处理`。
3. ❌ **禁止注释掉的死代码**：禁止 `# 旧代码 xxx` 后保留大段被注释的代码，应直接删除（Git 历史可追溯）。
4. ❌ **禁止无意义的逐行注释**：`# 赋值` `# 返回结果` 这类废话注释禁止。
5. ❌ **禁止注释与代码不一致**：修改代码时必须同步更新注释，注释过期比无注释危害更大。
6. ❌ **禁止在注释中写临床结论**：代码注释不得出现"该患者不适合缓解"等临床判断性结论，只能说明"代码如何处理某类输入"。临床结论只能由医生在软件运行时作出。
