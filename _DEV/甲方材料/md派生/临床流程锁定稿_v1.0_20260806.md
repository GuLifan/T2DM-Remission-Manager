# 二、软件目标与边界

* 服务于成人早期2型糖尿病患者缓解机会的规范化识别、主动管理、缓解判定及后续监测。
* 帮助医生快速识别值得进一步评估的患者，形成个体化管理方向和阶段目标，并规范缓解判定与复发后返回路径。
* 软件提供分层、提示、下一步和时间提醒，但不替代医生诊断、处方、停药及缓解确认。
* 当前阶段不建设个人缓解概率模型，不把任何单一评分或阈值作为刚性准入标准。

# 三、已锁定的设计原则

1. 正式路径前保留“60秒医生预评估”，避免所有T2DM患者自动建立完整缓解病例。
2. 预评估只产生三类主结论：进入完整评估；暂缓进入、完成前置处理后复评；当前不启动。
3. 急性安全、分型存疑和真正影响判断的关键资料缺失属于“暂缓原因”，不是与三类结论并列的新节点。
4. 病程超过5年、BMI正常、HbA1c较高、正在使用胰岛素或C肽暂缺，均不得单独触发排除。
5. ABCD等工具仅作为筛查启发和机会分层，不能直接决定准入或输出个体缓解概率。
6. 完整评估、是否启动主动管理、当前阶段和阶段目标，在同一临床决策事件中完成，避免连续重复步骤。
7. 主动管理只保留“血糖稳定”和“缓解诱导”两个可选阶段；生活方式、降糖调整、体重管理药物和代谢手术评估是可组合干预，不是互斥路径。
8. 减药和停药属于阶段复评中的治疗决定；停用最后一种具有降糖作用的药物后，由系统自动进入缓解观察期。
9. 继续使用具有降糖作用的心肾或体重获益药物时，不为获得缓解标签而停药；可记录治疗下血糖状态，但不能正式确认无药缓解。
10. 关键临床结论必须由医生确认；前台使用自然语言，不用工程编号或规则代码组织医生操作。

# 五、事件1｜60秒缓解预评估

本事件只判断患者目前是否值得进入完整评估，不判断患者最终能否缓解。

| **项目** | **锁定内容** |
| --- | --- |
| 临床问题 | 现在应进入完整评估、先处理前置问题，还是现阶段不建立主动缓解管理路径？ |
| 必需判断 | 成人T2DM判断是否基本成立；当前有无急性不安全状态；是否存在明显分型疑点；当前治疗背景是否足以判断；患者是否明确拒绝进一步了解或参与。 |
| 机会信息 | 大致病程、BMI或中心性肥胖线索、近期血糖状态、胰岛素使用背景、患者减重／减药／缓解诉求。机会信息暂缺通常不阻断。 |
| 三类输出 | ①进入完整缓解评估；②暂缓进入，完成前置处理后复评；③当前不启动缓解管理路径。 |
| 暂缓要求 | 必须同时给出暂缓原因、需要完成的前置事项和完成后的返回位置。 |
| 医生确认 | 是否基本可按T2DM理解；当前是否安全；分型疑点是否足以影响下一步；是否发起完整评估。 |

|  |
| --- |
| **不得将病程长、BMI正常、使用胰岛素、HbA1c高或C肽缺失自动转换为“不适合缓解”。** |

# 六、事件2｜完整评估并形成主动管理计划

本事件把“完整评估、是否启动主动管理、当前阶段和第一阶段目标”合并为一次医生决策。

| **评估维度** | **普遍必需／条件性内容** | **如何影响决定** |
| --- | --- | --- |
| T2DM基础与病程 | 诊断基础、大致病程、是否仍有未解决分型疑点。 | 决定能否继续按T2DM管理；病程只作机会分层。 |
| 当前血糖与治疗 | 最近HbA1c或可靠近期血糖；当前降糖治疗；胰岛素使用背景；是否处于重大治疗调整期。 | 确定血糖稳定或缓解诱导的起点及治疗安全。 |
| 体重状态 | 体重、身高或BMI；必要时腰围；近期明显增减重。 | 判断体重驱动因素和目标，不作为刚性准入。 |
| 胰岛功能 | 已有结果则使用；仅在分型、长期胰岛素依赖或减停药决策明显受影响时定向补充。 | 形成支持／限制因素；C肽不是全员通行证。 |
| 管理约束 | 只记录会改变方案的CKD、ASCVD／心衰、严重视网膜病变、低血糖、衰弱及相关用药。 | 调整饮食、运动和药物策略，不自动排除。 |
| 实施条件 | 患者是否愿意参与至少一种可行干预并接受阶段复评。 | 决定是否建立结构化主动管理。 |

| **医生一次性完成的决定** | **可选结果** |
| --- | --- |
| 是否启动主动管理 | 启动／暂缓补充关键资料／当前不启动。 |
| 当前管理阶段 | 血糖稳定阶段／缓解诱导阶段。两个阶段可直接进入或相互转换，不要求依次走完。 |
| 一个主要阶段目标 | 如安全改善明显高血糖；实现有临床意义的体重和代谢改善。 |
| 干预组合 | 结构化生活方式、降糖治疗调整、体重管理药物、代谢手术评估，可多选。 |

# 七、事件3｜阶段复评与治疗调整

这是主动管理期间唯一反复出现的医生决策事件。日常滴定、上传血糖和一般随访不自动生成正式节点。

| **最少输入** | **作用** |
| --- | --- |
| 新发生的安全问题 | 识别低血糖、明显高血糖、药物不良反应、营养风险或急性疾病。 |
| 一个主要阶段指标 | 血糖稳定阶段看近期血糖趋势；缓解诱导阶段看主要体重／血糖进展。 |
| 治疗变化 | 记录新增、减量、停用或无法继续的核心治疗。 |
| 实际可执行性 | 判断患者能否继续、需要调整还是结束主动路径。 |

| **输出** | **下一步** |
| --- | --- |
| 继续当前阶段 | 维持主要目标和方案，设置下一复评节点。 |
| 调整方案或目标 | 仍留在当前阶段，不重新进行完整评估。 |
| 转换管理阶段 | 血糖稳定与缓解诱导之间转换，由医生确认。 |
| 结束主动管理 | 返回常规糖尿病综合管理；以后临床条件改变可重新发起。 |
| 治疗下血糖达非糖尿病范围，暂不能判定缓解 | 适用于继续使用具有降糖作用的心肾或体重获益药物；不提示停药。 |
| 停用最后一种具有降糖作用的药物 | 系统记录日期并自动进入缓解观察期；不新增停药节点。 |

|  |
| --- |
| **缓解诱导阶段可默认约12周进行一次正式阶段复评；短期强化结束、重大治疗变化或安全事件可提前触发。该时间属于软件默认设计，可由医生调整。** |

# 八、自动状态｜缓解观察期

| **项目** | **系统处理** |
| --- | --- |
| 进入触发 | 停用最后一种具有降糖作用的药物。 |
| 时间锚点 | 最后一种降糖作用药物停用日期；结构化生活方式干预开始日期；代谢手术日期（如适用）；判定指标检测日期。 |
| 自动任务 | 计算最早可判定日期；到期提醒录入或检查判定指标。 |
| 退出方向 | 因血糖升高重新用药或需要强化治疗→返回阶段复评；到达最早判定日期→进入缓解判定。 |
| 非节点原则 | 医生不需要点击“进入观察期”，也不重新完成预评估或完整评估。 |

# 九、事件4｜缓解判定

系统先核对客观条件，医生再一次确认是否形成“2型糖尿病缓解”临床结论。

| **核心条件** | **锁定规则** | **性质** |
| --- | --- | --- |
| 既往诊断 | 既往T2DM诊断可信，不是短暂应激性或诊断依据不足的高血糖。 | 软件临床前提 |
| 用药状态 | 已停用全部具有降糖作用的药物至少3个月。 | 缓解定义 |
| 干预等待期 | 生活方式干预开始至少6个月；代谢手术后至少3个月；与停药3个月条件取较晚日期。 | 国际共识时间规则＋软件整合 |
| 首选指标 | HbA1c＜6.5%，且结果可可靠解释。 | 缓解定义 |
| 替代指标 | HbA1c不可靠时，才使用FPG＜7.0 mmol/L或CGM估算HbA1c＜6.5%；替代结果需独立复核。 | 共识建议 |
| 医生确认 | 诊断、停药时间、指标可靠性和时间条件均可信后，医生确认缓解。 | 必须由医生决定 |

| **系统状态** | **自然语言输出** |
| --- | --- |
| 尚未到达最早判定日期 | 目前处于缓解观察期，最早可于×年×月×日进行正式判定。 |
| 持续使用降糖作用药物 | 当前血糖已改善，但仍在使用具有降糖作用的药物，暂不能确认无药物缓解。 |
| 客观标准满足 | 当前客观资料符合T2DM缓解标准，请由医生确认。 |
| 当前未达到 | 当前未达到T2DM缓解标准，继续主动管理或调整方案。 |
| 指标暂不能解释 | 当前资料不足以可靠确认或排除缓解，请完成定向复核。 |

|  |
| --- |
| **继续使用具有降糖作用的SGLT2抑制剂、GLP-1受体激动剂等器官或体重获益药物时，不建议为获得缓解标签而停药；只能记录治疗下血糖状态，不能正式确认无药缓解。** |

# 十、事件5｜缓解后复评

| **最少输入** | **说明** |
| --- | --- |
| 当前血糖指标及日期 | 判断是否仍处于低于糖尿病诊断阈值的范围。 |
| 当前是否使用具有降糖作用的药物及原因 | 区分仍可评价无药缓解、因器官获益用药不可评价、因高血糖重新用药。 |
| 辅助触发信息 | 体重反弹、急性疾病、糖皮质激素、妊娠、手术或明显生活方式改变，用于提前复评。 |

| **状态** | **下一步** |
| --- | --- |
| 缓解维持 | 继续现有体重和生活方式管理，按计划复查。 |
| 仍维持缓解，但风险上升 | 加强维持干预，由医生决定是否提前复查；不定义“前复发期”。 |
| 当前缓解状态不可评价 | 因重新使用具有降糖作用的器官／体重获益药物；保留既往缓解历史，不等同于复发。 |
| 缓解状态终止 | 血糖再次达到糖尿病范围或因高血糖重新启用药物；直接返回主动管理。 |

|  |
| --- |
| **默认随访：第1年每3～6个月；第2年每6个月；满2年后每年。系统给出默认提醒，医生可根据异常结果或临床事件提前调整。** |

# 十一、返回路径锁定

| **场景** | **返回位置** |
| --- | --- |
| 预评估暂缓：分型存疑 | 结果明确为T2DM→直接进入事件2；明确为其他类型→关闭T2DM缓解路径。 |
| 预评估暂缓：急性不安全 | 完成急性处理后，根据状态进入事件1结论处或直接进入血糖稳定阶段。 |
| 事件2关键资料缺失 | 资料补齐后返回事件2结论处，不重复入口。 |
| 主动管理效果不足 | 留在事件3调整，不返回完整评估。 |
| 明显血糖失控 | 返回血糖稳定阶段；出现急症时先按常规急症处理。 |
| 观察期重新用药 | 因高血糖重新用药→事件3；因器官获益用药→记录暂不能判定状态。 |
| 未达到缓解标准 | 直接返回事件3继续管理。 |
| 缓解状态终止 | 直接返回事件3；仅新分型证据或重大临床变化时才返回事件2。 |

# 十二、三个病例端到端走查

| **病例** | **关键流程** | **必须避免的错误** |
| --- | --- | --- |
| 病例1：新诊断肥胖，HbA1c 10.6%，短期胰岛素强化，临床稳定 | 事件1进入→事件2启动血糖稳定阶段→事件3转缓解诱导→停最后一种降糖药后自动观察→满足时间与HbA1c条件→医生确认缓解。 | 不能因严重高血糖或胰岛素治疗而排除；不能把停药设为独立节点。 |
| 病例2：38岁消瘦、早期胰岛素、起病有酮症线索 | 事件1暂缓并复核分型→若证实自身免疫性糖尿病则关闭本路径；若仍为T2DM则直接进入事件2。 | 不能因BMI正常、胰岛素或C肽缺失直接判定不适合；暂缓必须有前置任务和返回位置。 |
| 病例3：HbA1c 5.9%，因CKD继续SGLT2抑制剂 | 事件2／3继续主动综合管理→形成“治疗下血糖达非糖尿病范围、暂不能判定缓解”状态。 | 不能提示为获得缓解标签而停用器官保护药物；不能错误标记为已缓解或缓解失败。 |

# 十三、学生实施时不可自行改变的边界

* 不得增加新的医生临床节点，确需新增时必须先提交问题及影响，由项目负责人确认。
* 不得把ABCD、病程、BMI、HbA1c、胰岛素使用或C肽结果转化为刚性准入分数。
* 不得把急性安全、分型存疑、资料缺失设计为与三类预评估主结论并列的永久状态。
* 不得设计自动停药、自动减药或为了确认缓解而停用器官保护药物的提示。
* 不得在多个页面重复收集病程、BMI、分型、C肽和并发症；后续只更新变化信息。
* 不得让旧页面架构、旧规则代码或历史任务书覆盖本锁定稿。
* 无法确定的内容应进入统一问题清单，不得由学生自行补充医学阈值。

# 十四、医学依据的标注规则

| **标注** | **含义** | **示例** |
| --- | --- | --- |
| 指南／共识明确规定 | 原始文件给出定义、时间或阈值，实施时应保留出处。 | 无降糖药至少3个月且HbA1c＜6.5%的缓解定义。 |
| 指南／共识倾向性建议 | 用于支持分层或管理方向，不转化为刚性排除。 | 短病程、超重肥胖、较好胰岛功能更有利于缓解。 |
| 软件设计决定 | 为提高门诊效率和减少无用步骤而作出的项目决定。 | 5类医生事件＋1个自动状态；每阶段只设一个正式复评点。 |
