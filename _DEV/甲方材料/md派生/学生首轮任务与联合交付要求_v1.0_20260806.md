# 一、团队工作方式

|  |
| --- |
| **项目负责人、临床学生和代码学生建立三人工作群。两名学生自行商量分工，但必须围绕同一份《临床流程锁定稿》工作，并共同提交一个整合版本。** |

* 学生可以自行决定谁主导临床流程整理、状态图、低保真原型和病例走查，不要求机械地按专业完全切开。
* 临床内容与软件实现必须一一对应；不得分别提交两套互相对不上的材料。
* 项目负责人主要确认临床逻辑和关键选择，不负责替学生逐项设计字段、按钮或代码。
* 遇到医学规则不明确或材料冲突时，统一列入问题清单，在群内集中确认，不得自行决定。

# 六、工作包A｜临床流程实现表的具体要求

按以下6个流程单元整理，不再增加临床单元：

| **序号** | **流程单元** | **性质** |
| --- | --- | --- |
| 1 | 60秒缓解预评估 | 医生决策事件 |
| 2 | 完整评估并形成主动管理计划 | 医生决策事件 |
| 3 | 阶段复评与治疗调整 | 可重复的医生决策事件 |
| 4 | 缓解观察期 | 系统自动状态，不是医生页面节点 |
| 5 | 缓解判定 | 医生确认事件 |
| 6 | 缓解后复评 | 可重复的医生决策事件 |

每个流程单元至少包含以下9列：

| **列名** | **填写要求** |
| --- | --- |
| 临床问题 | 这一单元究竟要作出什么决定。 |
| 必需输入 | 缺少后不能形成本单元结论的信息；每项必须真实影响分支。 |
| 条件性输入 | 仅在特定疑点、特定干预或特定状态下才需要。 |
| 不阻断的缺失信息 | 暂缺时仍可继续，例如多数场景下的C肽、腰围或CGM。 |
| 分支条件 | 说明信息如何改变下一步，不能只写“综合评估”。 |
| 系统自然语言输出 | 医生实际看到的结论、原因和下一步。 |
| 医生确认内容 | 哪些结论系统不能自动作出。 |
| 下一状态／返回位置 | 每个分支都必须有出口；暂缓必须明确完成后返回哪里。 |
| 依据性质 | 指南明确规定／指南倾向性建议／软件设计决定，并标注依据文件。 |

|  |
| --- |
| **检查原则：一项信息如果无论如何填写都不改变分支、输出或医生决定，应删除或降为非必需。** |

# 七、工作包B｜状态转换图的具体要求

* 必须清楚区分：医生操作事件、系统自动状态、信息标签和返回路由。
* 必须完整呈现5类医生决策事件＋1个自动观察状态，不按旧页面编号重新组织。
* 每个“暂缓”必须显示前置任务和完成后的返回位置。
* 停用最后一种具有降糖作用的药物后，系统自动进入缓解观察期；不得新增“停药确认页面”。
* 缓解状态终止后直接返回主动管理；普通效果不足不得返回60秒入口。
* 需进行无出口检查：所有状态均能到达下一步、常规管理或关闭路径。

# 九、工作包D｜三个病例走查

| **病例** | **必要输入特征** | **预期关键结果** |
| --- | --- | --- |
| 1｜早期肥胖＋严重高血糖但稳定 | 43岁女性；T2DM 4个月；BMI 31；HbA1c 10.6%；短期胰岛素强化；无酮症／危象；愿意减重。 | 不得因高HbA1c或胰岛素排除；进入血糖稳定阶段，后可转缓解诱导；停最后一种降糖药后自动观察。 |
| 2｜消瘦＋早期胰岛素＋分型存疑 | 38岁男性；BMI 21；起病体重下降和酮尿；诊断后很快用胰岛素；C肽／抗体未查。 | 预评估输出暂缓并复核分型；证实其他类型则关闭本路径；仍为T2DM则直接进入完整评估。 |
| 3｜血糖达非糖尿病范围但继续器官保护药 | 52岁女性；T2DM 2年；BMI 28；CKD／蛋白尿；SGLT2抑制剂；减重10%；HbA1c 5.9%。 | 不得提示停用器官保护药；输出“治疗下血糖达非糖尿病范围，暂不能判定缓解”。 |

走查表至少记录：步骤、输入、预期输出、原型实际输出、是否一致、问题严重程度、建议处理、是否需要医生确认。

# 十一、学生不可自行改变的临床边界

1. 不自行增加医生临床节点；状态、标签和自动规则不得伪装成新临床步骤。
2. 不把ABCD、病程、BMI、HbA1c、胰岛素或C肽转化为刚性准入分数。
3. 不把病程长、BMI正常、使用胰岛素、HbA1c较高或C肽缺失自动输出为“不适合缓解”。
4. 不自动建议减停药物；尤其不得为获得缓解标签而提示停用具有心肾或体重获益的降糖作用药物。
5. 不自行设置指南未明确支持的医学阈值和固定时间；有疑问进入统一问题清单。
6. 不从旧规则库、旧页面架构或历史任务书中恢复本锁定稿已删除的步骤。
7. 不把“治疗下血糖达非糖尿病范围”误写为已缓解、缓解失败或必须停药。

# 十三、首轮验收标准

| **验收项** | **通过标准** |
| --- | --- |
| 流程一致性 | 与《临床流程锁定稿》一致，没有擅自新增、删除或改变临床节点。 |
| 门诊效率 | 完整评估、是否启动、阶段和目标不被拆成连续重复操作；相同信息只录入一次。 |
| 病例正确性 | 3个病例均无错误排除、无错误缓解确认、无错误停药提示。 |
| 返回路径 | 暂缓、资料补充、观察期重新用药、缓解未达标和缓解终止均有明确返回位置。 |
| 自然语言输出 | 医生能够直接理解当前结论、原因和下一步，不依赖规则代码。 |
| 问题质量 | 问题具体、去重，并包含学生建议；不把可自行实现的技术细节全部转交项目负责人。 |
