# ETMMS 0.4.3 当前有效约束

## 用途与权威

本完整交付对应产品0.4.3，仅录入模拟资料用于公网验收。临床契约v0.3、输入v0.4、数据库head d04data001。应用行为沿用已批准并验证的源码基线，发布整理不增加医学规则。

临床转移及输出以[机器可读契约](../backend/app/domain/clinical_v03_contract.json)和对应服务为准，保留51个原始及7个已批准补充转移。不得从包装文案推导新医学阈值，不擅自清理历史事实或原始来源。

## 账号、权限和日期

- 首位管理员交互创建；邀请码由管理员发放，医生注册后病例为空。
- 医生只访问自己的病例；管理员的既有管理权限由服务器校验。历史、资料引用、补正、下载均核对身份、病例归属和归档状态。
- 普通医生使用真实系统日期，不能修改业务日。管理员列表和病例页头左侧直接打开日期窗口，只影响当前管理员；保留管理区入口及日期审计。
- 日期或身份变化撤下旧判定资格、阻断旧草稿；跨标签同步身份。界面隐藏不能替代后端权限。
- 归档并新建保留旧记录、使旧轮次只读，复制基本资料开启空白临床轮次，不删除事件或带入旧结论。

## 输入、默认和沿用

- 病程年/月独立可空，均空表示未知，0不同于空。填年时月0—11；只填月时18个月有效。不补造诊断日期。
- E1测量可选；E2首次启动需要基线体重和已确认身高，暂缓/不启动不由启动分支隐藏必填阻断。后续引用已有测量保留原测量日，也可新增；BMI显示一位小数。
- A04、B07、B09留空；新检查来源默认本院检查、可靠性默认可靠。既有药物和体重带入是参考，不替代必须本次作出的确认。其他已有已批准初值保持，页面预填不等于保存。
- 检查独立保存指标/数值或摘要、单位、日期或区间、来源及可靠性。HbA1c用%、FPG用mmol/L。摘要型资料不能冒充缓解判定指标。
- 药名保留手输，常用目录按类别多选新增独立卡片；目录不自动推断剂量、作用或用途。多种用药目的并列保存。开始时间保留年/年月/完整日/未知精度，不补造某月首日。
- 管理计划与实际干预、计划停药与实际停药分别保存；其他干预说明随已保存计划沿用。

## 药物方案

- 使用最新完整方案，不向前搜索旧非空列表来恢复已停用/已移除药物。旧不完整空列表仍为未知，不能直接推断无药。
- 可从本次方案移除既有卡片。保存声明removed_medication_ids，服务器核对最新来源、修订及准确差集，拒绝伪造/遗漏/重复ID。移除后完整核对失效，全部移除另需no_current_medications_confirmed明确为true。
- 保存追加新方案，既有方案/事件保留。移除不生成实际停药状态、日期或观察锚点；同次声明实际全部停药时，仍须保留相关降糖药卡，逐药核对实际状态和完整日期。
- 用药明细、作用和本次核对结论必须一致，矛盾历史需本次明确核对，不批量猜测或改写旧事实。获益用药入口仍检查完整方案、用途与资料版本。

## 日期和判定

- 既往及当天检查可记录；已发生的检查、测量和实际停药不采用未来日期，错误说明所填日期和当前业务日。下次复评是计划，可以在未来。
- E4只使用已支持的HbA1c、FPG或CGM估算HbA1c，显式选定检查并继续核对可靠性、解释性、替代指标复核、阈值、用药及日期。
- 实际停药和适用干预按原日历月规则计算最早可判定日。界面显示最早日—当前业务日的闭区间；区间之前的检查可保留历史，但不能用于本轮确认。未知最早日提示核对锚点，不捏造日期。
- 客观核对不自动确认缓解。医生独立确认绑定当前身份、日期、资料修订和客观快照；修改相关资料后旧资格失效。不得移除医学等待期限来消除提示。

## 数据、并发和补正

- 每次成功临床保存显式升版，同值保存也通过条件UPDATE阻断竞争。request_id幂等、expected_revision和方案来源门禁保留。
- 当前记录、事件、患者快照及审计同事务。读接口不新增事件或推进流程；外部变化保留草稿并阻断提交，只有明确载入最新资料才放弃草稿。
- 补正追加前后值、原因、操作者及时间，不回写原结论。引用均核对本病例与有效版本。兼容读取保留原编号、来源、日期性质和未知，不对自由文本批量替换。
- 临床/输入版本标识、兼容入口、旧数据读取与迁移链保留；它们是当前运行依赖，不属于可丢弃的旧发布材料。

## 界面反馈

提交校验/服务端错误/E4未通过结果居中提示，支持返回、Escape及定位字段，保留草稿。结果位于不会随表单修订号重建而丢失的层级，切换病例/身份/日期撤下旧结果。关闭后可在底部再次查看。补正错误位于原补正窗口。沿用当前CSS Token及焦点管理。
