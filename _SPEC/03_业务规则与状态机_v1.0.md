## 一、状态全集（ST00–ST99，共 9 个）

| 状态代码 | 锁定名称 | 定义/场景 | 性质 | 开发注意 |
| --- | --- | --- | --- | --- |
| ST00 | 常规糖尿病综合管理 | 未启动或已结束本次主动缓解管理路径；后续条件改变可重新发起60秒预评估 | 医生工作状态 | 前台显示自然语言，不显示内部状态代码 |
| ST10 | 60秒缓解预评估 | 判断进入完整评估、暂缓或当前不启动 | 医生决策事件 | 暂缓原因作为标签和前置任务，不另设医生临床节点 |
| ST20 | 完整评估并形成主动管理计划 | 一次性完成是否启动、当前阶段、一个主要阶段目标和干预组合 | 医生决策事件 | 不得拆成连续重复页面 |
| ST31 | 主动管理—血糖稳定阶段 | 主要目标为安全改善明显高血糖或保障治疗安全 | 管理状态 | 与缓解诱导阶段可直接进入或相互转换 |
| ST32 | 主动管理—缓解诱导阶段 | 主要目标为有临床意义的体重和代谢改善 | 管理状态 | 生活方式、降糖调整、体重管理药物及代谢手术评估可组合 |
| ST40 | 缓解观察期 | 停用最后一种具有降糖作用药物后由系统自动进入 | 系统自动状态 | 不是医生页面，不新增"停药确认页面" |
| ST50 | 缓解判定 | 系统核对客观条件，医生确认是否形成T2DM缓解临床结论 | 医生确认事件 | 系统不得自动确认缓解 |
| ST60 | 缓解后复评 | 重复评估缓解维持、风险上升、不可评价或缓解终止 | 可重复医生决策事件 | 缓解终止直接返回主动管理 |
| ST99 | 关闭T2DM缓解路径 | 分型复核明确为其他类型糖尿病 | 关闭路径 | 不等同于常规T2DM管理状态 |

## 二、状态出口矩阵（无出口检查基线）

> 由 `_DEV` 状态转换速览 38 条转换归纳；任何状态不得存在无出口情况。

| 源状态 | 出口（目标状态） | 触发规则 |
| --- | --- | --- |
| ST00 | ST10（条件改变后重新发起） | 医生重新发起预评估 |
| ST10 | ST20 / ST10（暂缓，自环） / ST00 / ST99 | E1-B01…B05 |
| ST20 | ST31 / ST32 / ST20（暂缓，自环） / ST00 | E2-B01…B04 |
| ST31 | ST31（自环）/ ST32 / ST00 / ST40 | E3-B01/B02/B03/B05/B07；E3-B08 自环回 ST31 |
| ST32 | ST32（自环）/ ST31 / ST00 / ST40 | E3-B01/B02/B04/B05/B07 |
| ST40 | ST40（自环）/ ST50 / ST31或ST32（因高血糖重新用药，阶段由医生选择，2026-08-23 裁决）/ ST31或ST32（器官/体重获益用药） | A1-B01…B05 |
| ST50 | ST40 / ST31或ST32 / ST50（自环）/ ST60 / ST20（仅新分型证据或重大临床变化；F041=否 亦返回 ST20 复核，2026-08-23 裁决） | E4-B01…B07 |
| ST60 | ST60（自环）/ ST31或ST32 / ST20（仅新分型证据或重大变化） | E5-B01…B05 |
| ST99 | 无出口（路径关闭，终态） | 分型复核明确为其他类型 |

**关键转换语义（锁定稿原文）**：

1. **进入观察期**：停用最后一种具有降糖作用的药物 → 系统记录日期并自动进入 ST40；**不新增停药节点、不新增"进入观察期"操作**（锁定稿§7/§8）。
2. **观察期退出**：因血糖升高重新用药或需要强化治疗 → 返回阶段复评（事件3）；到达最早判定日期 → 进入缓解判定（锁定稿§8）。
3. **缓解终止**：直接返回事件3；**仅新分型证据或重大临床变化才返回事件2**（锁定稿§11）。
4. **暂缓返回**：每个"暂缓"必须显示前置任务和完成后的返回位置（任务书§7）。

## 三、医学边界规则（R-MED，锁定，不可实现为自动裁决）

| 编号 | 规则 | 依据性质 |
| --- | --- | --- |
| R-MED-01 | 病程长、BMI正常、HbA1c高、使用胰岛素、C肽缺失——任何单项都不得单独触发排除或"不适合缓解"。 | 指南/共识倾向性建议 + 软件设计决定 |
| R-MED-02 | ABCD等工具仅作筛查启发和机会分层，不决定准入，不输出个体缓解概率。 | 软件设计决定 |
| R-MED-03 | 急性安全、分型存疑、关键资料缺失只是暂缓原因，不得成为与三类预评估结论并列的永久状态。 | 软件设计决定 |
| R-MED-04 | 减药/停药是阶段复评中的治疗决定，必须由医生作出；系统不自动停药减药。 | 软件设计决定 |
| R-MED-05 | 继续使用具有降糖作用的 SGLT2 抑制剂、GLP-1 受体激动剂等器官/体重获益药物时，不建议为获得缓解标签而停药；只记录"治疗下血糖达非糖尿病范围"，不能确认无药缓解。 | 指南/共识明确规定 + 软件设计决定 |
| R-MED-06 | 缓解定义：停用全部具有降糖作用的药物至少3个月，且 HbA1c＜6.5%；替代指标仅当 HbA1c 不可靠时使用（FPG＜7.0 mmol/L 或 CGM 估算HbA1c＜6.5%），替代结果必须独立复核。 | 指南/共识明确规定 |
| R-MED-07 | 既往T2DM诊断可信是缓解判定的软件临床前提；不是短暂应激性或诊断依据不足的高血糖。 | 指南/共识明确规定 + 软件设计决定 |
| R-MED-08 | 干预等待期：生活方式干预开始至少6个月；代谢手术后至少3个月；与停药3个月条件**取较晚日期**。 | 国际共识时间规则 + 软件整合 |
| R-MED-09 | 缓解判定最终临床结论必须由医生确认；系统只核对客观条件并阻断不合规操作。 | 软件设计决定 |
| R-MED-10 | "治疗下血糖达非糖尿病范围"不得误写为已缓解、缓解失败或必须停药；因器官/体重获益用药造成的不可评价不得等同于复发。 | 指南/共识明确规定 + 软件设计决定 |
| R-MED-11 | 不定义"前复发期"等锁定稿未出现的临床状态。 | 软件设计决定 |
| R-MED-12 | 缓解不等于治愈；缓解后仍需监测和常规并发症管理。 | 指南/共识明确规定 |

## 四、时间与提醒规则（R-TIME）

| 编号 | 规则 | 默认值 | 可调性 | 出处 |
| --- | --- | --- | --- | --- |
| R-TIME-01 | 缓解诱导阶段正式复评默认间隔 | 约12周 | 医生可调整；短期强化结束、重大治疗变化或安全事件可提前触发 | 锁定稿§7 |
| R-TIME-02 | 血糖稳定阶段正式复评默认间隔 | 约12周（2026-08-23 裁决，软件设计决定） | 医生可调整；短期强化结束、重大治疗变化或安全事件可提前触发 | 锁定稿§7；`06` 裁决 |
| R-TIME-03 | 最早可判定日期 F040 | MAX(停药+3月；生活方式干预+6月〔如适用〕；代谢手术+3月〔如适用〕)，按日历月加法；月末钳位到目标月最后一天（8月31日+3月=11月30日，2026-08-23 裁决） | 系统计算，不适用锚点不参与 | 锁定稿§8；字段映射 F040；`06` Q001 |
| R-TIME-04 | 缓解后随访节奏 | 第1年每6个月（默认，2026-08-23 裁决）；第2年每6个月；满2年后每年 | 系统给默认提醒，医生可根据异常结果或临床事件提前调整 | 锁定稿§10；`06` 裁决 |
| R-TIME-05 | 观察期到期检查 | 当前日期≥F040 时开放判定（按日或登录时计算即可；本版本不建设后台高频任务） | 系统 | 锁定稿§8；A1-B02/B03 |

> 日历月加法（add_months）的月末边界语义已裁决（2026-08-23）：钳位到目标月最后一天（如 8月31日+3个月=11月30日），见 `06_问题清单与裁决记录` Q001。
