## 一、审阅方式（先说清楚结论是怎么来的）

| 项目 | 说明 |

| 未走到的页面 | 缓解后复评、关闭路径、急性安全快速建档（**这些页面的问题在本文件中标注为"未实测"**，供你判断是否要先看） |
| 对照标准 | Jakob Nielsen《十大可用性启发式》；GOV.UK 设计系统（表单模式，含"一次只问一件事"）；NHS 设计系统（英国 NHS 服务手册） |
| 截图证据 | 本文件同目录 `审阅截图/review_01…07.png` |

### 我这次审阅暴露出的根本问题（自我反省，写在最前面）

我把界面当成"**把后端已有的字段都摆出来**"来做，而不是按"**医生在门诊那 3 分钟里要做的动作**"来设计。结果就是：

- 工程概念直接搬到了界面上（"未生效的分支""客观条件""实际可执行性"）；
- 一屏里塞进所有可能用到的输入项，哪怕 90% 的情况只用得上其中两三个；
- 系统状态和病人状态混在一起展示，甚至出现与事实不符的标签（见 UX-01）。

这三点是下面绝大多数问题的**同一个根因**。

## 三、系统性设计问题：视觉引导与视觉焦点缺失（由 Lifan 于 2026-09-21 提出）

> **Lifan 的原始判断**："整个软件重点不明，缺乏良好的视觉引导和视觉焦点，这会使人学习成本上升、使用过程疲劳。"
>
> **我的评价**：这一条比前面 33 条更根本。前面那些是"点"上的毛病，这一条是**整页没有主次**；
> 而且它是很多具体问题的**共同原因**——因为没有层级，医生只能逐块读完才知道该做什么。

### 3.1 实测证据（每条都可核对）

| # | 证据 | 位置 / 具体数值 | 医生会怎样 |
| --- | --- | --- | --- |
| E1 | **核心工作页面上最大的字只有 16px**，与普通小节标题同级；设计系统里 24px 的"页面主标题"层级**在工作页面里从未使用**（只出现在登录页） | `.page-header__title` 与 `.section__title` 都是 `--etmms-text-section-title`（16px）；`--etmms-text-page-title`（24px）仅用于 `.login-title` 与 `h1` | 一眼看不出"这页的主题是什么" |
| E2 | **所有区块视觉权重几乎相同**：卡片一律白底 + 1px 描边 + 24px 内边距，卡片之间也是 24px | `components.css` 的 `.card` / `.section` | 无法靠"分组感"跳读，只能逐块读 |
| E3 | **决策信息与参考信息同权**："本次管理记录"（事件流水）与决策表单用**完全相同的白卡样式**，而且常常更长 | `.event-item` 与 `.card` 同族样式 | 参考信息抢走注意力，决策区被淹没 |
| E4 | **医生还没做决定时，页面上没有任何视觉焦点**：唯一的两个强调元素——结果横幅（16px/600）与底部主按钮——一个**提交后才出现**，一个**固定在视口最底部** | `.result-banner__text`、`.action-bar`（sticky） | 打开页面第一眼不知道看哪里、更不知道先做什么 |
| E5 | **颜色失去指示性**：主色蓝同时用于主按钮、链接、导航选中、徽章底色、多选项选中底；绿色同时表示"满足缓解条件"与"已到最早可判定日期" | `--etmms-primary*`、语义色的实际用法 | 颜色不再能提示"哪里最重要" |
| E6 | **侧栏与主内容等权**：240px 常驻（1024 宽下占 23%），8 个可点项与主内容持续争夺注意力 | `.app-shell__nav` | 视线被不断拉走 |
| E7 | **没有完成度反馈**：必填与选填外观完全一致，也没有"已完成 x/y 项" | 六个流程页 | 医生必须自己记住还剩哪些没填 → 反复回看（Nielsen #6 识别优于回忆） |
| E8 | **长页面上视线往返距离过大**：阶段复评页实测三屏以上，表单在中部、主按钮固定在底部 | 阶段复评页 | 操作疲劳，容易漏看自己填过的内容 |

### 3.2 为什么会写成这样（我的判断，不是辩解）

1. **`UI.md` 定义了 Token 与组件，却没有定义"信息层级"**——没有一章说"什么内容应该比什么内容更醒目"。规范缺这一层，代码里自然就没有。
2. 我把"所有字段都要可见"误当成需求（怕医生找不到），结果**焦点被平摊到每一个字段上**。
3. 我用"卡片"作为唯一的分组手段；**卡片一多，卡片的强调作用就归零**。
4. 我把"结果"做得很醒目，却忘了"**过程**"也需要焦点——而过程恰恰是医生 90% 的时间所在。

### 3.3 对照标准

- **Nielsen 启发式**：#1 系统状态可见性、#6 识别优于回忆、#8 美学与极简设计——本软件三条都不满足。
- **GOV.UK 设计系统**：一页只问一件事 + 大标题 + 单一主按钮，焦点天然明确。
- **成熟临床系统（HIS/EMR）**：尽管普遍被诟病，但有一点是共识做法——**患者 banner 固定、当前任务标题醒目、结果区集中**。本软件这三点都不具备。

### 3.4 改进方向（供讨论，不是最终方案）

核心是引入**三级信息层级**，并在 `UI.md` 里写成强制条款：

| 层级 | 内容 | 视觉处理 | 约束 |
| --- | --- | --- | --- |
| **一级｜当前任务与结论** | 本次要做的决定、系统核对结论 | 页面最大字号 + 唯一强调容器 | **每页只允许一个** |
| **二级｜决策区** | 需要医生填/选的字段 | 标准卡片 + 明确必填标记 | 非当前分支的字段默认收起 |
| **三级｜参考信息** | 既往记录、时间锚点、系统说明、事件流水 | 降级：灰底 / 折叠 / 抽屉 | 不得与决策区同权 |

配套手段（8 条，供取舍）：

1. 工作页面恢复 **24px 页面主标题**，页头标题与内容区标题**不重复**（当前是两个标题打架，见 UX-12）。
2. 增加**"本次任务"焦点容器**：一句话说清"现在要做什么"，放在内容区顶部。
3. 必填项加标记；提供**完成度反馈**（如"还需填写 2 项"）。
4. 事件流水**降级**为折叠区或侧边抽屉，不再与决策区同权。
5. **收敛颜色语义**：蓝色只用于主行动；绿色只用于"达标/完成"；中性信息一律灰。
6. 建立**两级间距**：大分组 32px、小分组 8–12px，让"分组感"可以被看见。
7. 长页面把主按钮**就近放置**（或分段提交），减少视线往返。
8. 侧栏可收窄/折叠（如 56px 图标模式），把宽度还给决策区。

> ⚠️ 这一节如果要改，**必须先给 `UI.md` 增加一章"信息层级与视觉焦点规范"**，
> 否则改完仍然没有可依据的判断标准（详见第四节影响面表）。
