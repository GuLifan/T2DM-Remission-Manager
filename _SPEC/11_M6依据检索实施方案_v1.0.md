## 一、目标与边界

M6 的目标是在本机、离线环境中建立可重建的医学依据检索能力：医生输入关键词后，系统返回原始材料中的命中片段，并明确显示材料名和可复核位置。

本阶段只做“查阅与定位”，不做以下事项：

1. 不根据检索结果自动生成诊疗建议、患者结论或流程分支。
2. 不新增或修改任何临床阈值、状态、规则、字段或锁定文案。
3. 不做 OCR；遇到扫描件或空文本页时明确失败，不静默生成不完整索引。
4. 不把患者信息、病历内容或检索词发送到外部服务。
5. 不把原始 PDF、抽取全文或预构建检索库提交到 GitHub。
6. 不在 M6 内处理便携版对版权材料的再分发；该事项留到 M7 交付方案单独确认。

本方案落实 `_SPEC/06` V1.0-Q-05、`_SPEC/07` 第八节、`UI.md` 3.8 和 `_SPEC/08` M6 的既有裁决。

### 2.2 当前代码基线

- 后端已经依赖 `pypdf>=5.0`，无需引入新的 PDF 解析依赖。
- 数据库为 SQLite，当前运行环境为 SQLite 3.50.4，已启用 FTS5。
- `EvidenceDrawer` 已有静态组件和占位状态，但尚未接入接口，搜索词和结果当前均为固定空值。
- 后端尚无 `evidences`、`evidence_chunks` 数据模型、迁移、仓储、服务或接口。
- `_DEV/依据索引表_待填写_v1.0.csv` 有 36 条规则记录，当前依据字段均未填写。

### 2.3 中文检索兼容性结论

本机实测表明：

- FTS5 默认 `unicode61` 分词器不能可靠命中连续中文中的“缓解”“停药”“降糖作用”。
- FTS5 `trigram` 能命中 3 个及以上 Unicode 字符的连续片段。
- `trigram` 对 2 字中文词仍不能命中，因此不能把“FTS5 可用”直接等同于“中文检索可用”。

据此，M6 必须采用“FTS5 trigram 主检索 + 短词参数化 LIKE 兜底”，并用中文 2 字、4 字和英文查询分别验收。

## 三、待审批的约束决议

### M6-D01｜检索材料范围

**建议结论**：检索库包含“三份医学 PDF + 一份临床流程锁定稿 Markdown”。

- 三份 PDF 的出处显示为“材料名 + PDF 第 N 页”。
- 锁定稿的出处显示为“临床流程锁定稿 v1.0 + 章节名”。
- UI 必须区分“医学共识/指南”和“项目锁定依据”，不得把锁定稿伪装成公开医学指南。

理由：与 `_SPEC/06` V1.0-Q-05 一致，同时保留 `_SPEC/08` 所说“三份材料均可检索”的医学材料验收口径。

### M6-D02｜页码与章节定位

**建议结论**：PDF 页码统一采用从 1 开始的物理 PDF 页序，并在界面明确写成“PDF 第 N 页”，不推测期刊印刷页码；Markdown 采用一级章节名定位。

理由：物理页序可稳定复现，不受封面、目录和期刊连续页码影响；自动猜测印刷页码可能产生错误出处。

### M6-D03｜36 条规则索引表

**建议结论**：把索引表作为 M6 的独立临床资料 Gate，不由全文检索算法自动判定“哪条规则由哪份材料支持”。

实施时：

1. Codex 可逐条生成“依据性质、材料简称、位置、关键结论”的候选草案。
2. “原文摘录”默认留空或仅保留必要的短摘录，避免把大段版权正文提交到仓库。
3. 所有候选行标记为“待 Lifan/医学负责人复核”；未经复核不得写成“已确认依据”。
4. M6 工程功能可先完成，但 M6 最终交付 Gate 要求 36/36 行均有明确处理状态；若某规则属于软件设计决定或锁定稿约束，应如实标注，不能强行匹配医学文献。

### M6-D04｜检索审计与隐私

**建议结论**：所有登录用户都可检索全局依据；不需要患者归属权限。每次实际检索写入 `evidence_search` 审计，但审计中不保存原始检索词和命中正文。

审计只记录：操作者、结果数量、检索模式、查询字符数、时间。这样既能证明检索功能被使用，又避免医生误输入姓名、住院号后进入长期审计记录。

### M6-D05｜材料分发边界

**建议结论**：M6 只实现本地导入、索引与检索；原 PDF、抽取全文和运行数据库继续由 `.gitignore` 排除。M7 打包时再单独决定：

- 由有权使用材料的部署方在本机首次导入；或
- 在版权/授权确认后随交付包提供预建索引。

M6 不默认选择第二种方式。

## 四、数据模型与迁移方案

### 4.1 `evidences` 材料元数据

建议字段：

| 字段 | 约束 | 用途 |
| --- | --- | --- |
| `id` | 主键 | 内部标识 |
| `source_key` | 唯一、稳定 | 不依赖文件名的材料键 |
| `title` | 必填 | 界面显示材料名 |
| `source_type` | `pdf` / `markdown` | 决定定位方式 |
| `file_name` | 必填 | 导入来源文件名，不保存绝对路径 |
| `sha256` | 必填 | 判断材料是否变化、支持幂等导入 |
| `page_count` | PDF 必填，Markdown 为空 | 原始 PDF 总页数 |
| `text_page_count` | PDF 必填，Markdown 为空 | 成功抽取文本的页数 |
| `chunk_count` | 必填 | 当前有效分块数 |
| `imported_at` | 必填 | 最近成功导入时间 |

### 4.2 `evidence_chunks` 原文分块

建议字段：

| 字段 | 约束 | 用途 |
| --- | --- | --- |
| `id` | 主键 | 与 FTS 行号对应 |
| `evidence_id` | 外键、索引 | 所属材料 |
| `ordinal` | 材料内顺序；与材料联合唯一 | 稳定排序 |
| `page_no` | PDF 为 1 起始页码；Markdown 为空 | PDF 定位 |
| `section` | 可空 | Markdown 章节或 PDF 可识别章节 |
| `content` | 必填 | 供医生查阅的纯文本片段 |
| `search_text` | 必填 | 仅做空白规范化后的检索文本 |
| `char_count` | 必填 | 导入质量核对 |

分块不得跨越 PDF 页；Markdown 分块不得跨越一级章节。目标分块约 800–1,200 字符，允许约 120 字符上下文重叠。规范化只能处理空白和换行，不得改写、翻译或总结原文。

### 4.3 FTS5 虚拟表

迁移创建 `evidence_chunks_fts`，使用 `tokenize='trigram'`，并通过数据库触发器与 `evidence_chunks` 同步。迁移必须同时验证 FTS5 和 trigram 可用性；若运行环境不支持，普通表仍可工作，查询服务整体退化为参数化 `LIKE`，界面不得报假成功。

Alembic 迁移只建结构，不把版权材料或抽取文本写进迁移文件。

## 五、导入脚本方案

新增 `scripts/import_evidence.py`，使用项目内隔离环境运行。建议调用方式：

```powershell
cd backend
uv run python ../scripts/import_evidence.py --source-root ../_DEV
```

导入流程固定为：

1. 按稳定清单解析四个预期来源，缺文件即明确报错并返回非零退出码。
2. 计算 SHA-256；哈希未变化且数据库已有完整分块时跳过。
3. PDF 逐页抽取，保留 1 起始物理页码；Markdown 按一级章节抽取。
4. 输出每份材料的页数、文本页数、字符数、分块数和解析警告。
5. 任一 PDF 出现空文本页、总字符数异常过低或抽取异常时，该材料整份不替换旧索引。
6. 每份材料在单独事务内原子替换；失败不能留下半份新索引。
7. 重复运行不得产生重复材料或重复分块。
8. 不自动删除“本次源目录未出现”的既有材料，避免路径配置错误造成隐式数据删除。

导入器必须把解析器警告汇总给操作者；已知两份 PDF 的结构警告允许在“页数完整、无空页、字符数通过基线”时作为非阻断警告，但要进入导入报告。

## 六、接口契约

### 6.1 状态接口

`GET /api/evidence/status`

- 需要登录。
- 返回预期材料数、已就绪材料数、材料列表、最近导入时间和是否可搜索。
- 用于区分“尚未导入”和“已导入但当前查询无结果”。

### 6.2 检索接口

`GET /api/evidence/search?q=...&limit=20`

约束：

- 需要登录；管理员和普通医生权限一致。
- `q` 去除首尾空白后最少 2 个、最多 100 个 Unicode 字符。
- `limit` 默认 20，最大 50。
- 3 字及以上优先 FTS5 trigram；2 字或 FTS5 不可用时使用参数化 `LIKE`。
- 所有查询均参数化，不把用户输入拼入 SQL 或 FTS 表达式。
- FTS 查询按“原样短语”转义双引号；LIKE 查询显式转义 `%`、`_` 和转义符本身，用户输入不得被解释成查询操作符或通配符。
- 返回纯文本，不返回可执行 HTML；前端不得使用 `dangerouslySetInnerHTML`。
- 默认按匹配质量、材料顺序、页码和分块顺序稳定排序。

建议响应结构：

```json
{
  "query": "停药时间",
  "search_mode": "fts5_trigram",
  "materials_indexed": 4,
  "total": 3,
  "items": [
    {
      "evidence_id": 1,
      "title": "2 型糖尿病缓解中国专家共识",
      "source_type": "pdf",
      "page_no": 4,
      "section": null,
      "snippet": "……"
    }
  ]
}
```

“检索库未导入”返回可识别的业务错误和医生可读文案；“查询无命中”返回 200 与空列表。

## 七、前端交互方案

在现有 `EvidenceDrawer` 上接入，不另建第二套入口：

1. 打开抽屉先读取材料状态。
2. 未导入时显示“医学依据尚未导入，请联系系统维护人员完成本地导入”。
3. 已导入但未输入时显示材料数量和检索提示。
4. 输入不足 2 字时不发请求，并提示“请输入至少 2 个字符”。
5. 输入达到条件后延迟约 300 ms 检索；新查询必须取消旧请求，避免旧结果覆盖新结果。
6. 明确区分加载中、无结果、接口失败和材料未导入四种状态。
7. 每条结果显示片段、材料名，以及“PDF 第 N 页”或章节名。
8. 抽屉固定显示：“以下内容仅供查阅原始依据，不替代医生判断。”
9. 不出现“建议”“推荐本患者”“应停药”等由系统生成的临床行动文案。
10. 保留 Esc 关闭，并补齐打开后聚焦搜索框、关闭后焦点返回触发按钮、对话框焦点约束和无障碍标签。

## 九、测试与验收矩阵

### 9.1 导入与数据完整性

- 三份 PDF 共 152 页，验收时必须保持 152/152 页有文本；材料哈希变化时停止并重新核对基线。
- 锁定稿 15 个一级章节均能检索并显示章节出处。
- 分块不跨页/章；重复导入不重复；单份失败不破坏该材料旧索引。
- 缺文件、空页、扫描件、损坏 PDF、写库失败均有明确失败报告。
- 数据库迁移升级和降级路径在临时数据库验证，不直接依赖开发库。

### 9.2 检索正确性

最少覆盖：

| 查询类型 | 示例 | 预期 |
| --- | --- | --- |
| 中文 2 字 | `缓解` | 使用 LIKE 兜底且有命中 |
| 中文连续词 | `停药时间` | 使用 trigram 且有命中 |
| 英文/数字混合 | `HbA1c` | 有命中，结果出处正确 |
| 英文 | `remission` | 英文共识有命中 |
| 特殊字符 | 引号、百分号、下划线、FTS 操作符 | 不报 SQL/FTS 语法错误，不扩大为非预期通配 |
| 无结果 | 随机不存在词 | 200 + 空列表，不显示“未导入” |

### 9.3 权限、审计与隐私

- 未登录访问返回 401；管理员和启用中的普通医生均可检索。
- 搜索不读取或修改患者数据，也不受患者归属影响。
- 每次实际查询有审计；审计中没有原始查询、正文片段或患者病历。
- 接口响应和日志均不泄露本机绝对文件路径。

### 9.4 前端与浏览器

- 材料未导入、未输入、加载、无结果、错误和成功六类状态均可区分。
- 快速连续输入时只呈现最后一次查询结果。
- 出处文字与后端页码/章节一致；不渲染 HTML。
- 键盘可以打开、检索、浏览结果并关闭抽屉；焦点不会丢失。
- 在真实浏览器中核对中文、英文、短词、无结果和接口故障场景。

### 9.5 M6 最终 Gate

- 后端 pytest、ruff 全绿。
- 前端 Vitest、lint、TypeScript、Vite build 全绿。
- 文档检查 3/3 全绿。
- 四个来源均可搜索，三份 PDF 出处均能定位到 PDF 页；锁定稿定位到章节。
- 36/36 条规则索引均有明确状态，不把未复核候选写成已确认依据。
- 真实浏览器走查通过；临床规则、状态机和患者数据无回归。
- `develop` 经 Lifan 单独批准后方可推送；不得自动合并 `main`。

## 十、停止条件

出现以下任一情况立即停止对应批次并报告，不自行推断：

1. 三份 PDF 的哈希、页数或标题与本次核验基线不一致。
2. 任一 PDF 出现空文本页、文本量异常或页码无法稳定定位。
3. 材料之间的医学表述与临床流程锁定稿发生影响软件行为的冲突。
4. 规则索引某行无法判断是医学依据、锁定稿要求还是软件设计决定。
5. 运行环境不支持 FTS5/trigram，且 LIKE 降级的性能或准确性不满足验收。
6. M7 是否携带版权材料或预建全文索引需要作出超出本方案的分发决定。
