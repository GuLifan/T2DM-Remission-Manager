## 四、验收标准

### 4.1 流程与临床正确性（最高优先）

- ☐ 与《临床流程锁定稿》一致：9 状态、32 条规则、无擅自新增/删除/改变临床节点
- ☐ 3 个锁定病例端到端走通，且**无错误排除、无错误缓解确认、无错误停药提示**
- ☐ 全部状态无非法跳转、无无出口；每个"暂缓"均给出原因 + 前置任务 + 返回位置
- ☐ 停用最后一种降糖药后系统自动进入观察期，界面上不存在"停药确认页"或"进入观察期"按钮
- ☐ 继续使用器官/体重获益药物时，输出"治疗下血糖已达非糖尿病范围，暂不能判定缓解"，不提示停药
- ☐ 系统从不自动确认缓解；客观条件核对与医生确认是两个独立动作

### 4.2 界面与可用性

- ☐ 前台不出现状态代码、规则 ID、字段 ID
- ☐ 全部按钮为动词短语，无"确定/提交/是/否"
- ☐ 一个界面最多一个主按钮；底部动作条真实存在并被使用
- ☐ 分支互斥与优先级在界面上可见：高优先级分支覆盖低优先级时，必须给出明确说明
- ☐ UI Token 使用率 100%（无未使用 Token）；无 inline style
- ☐ 表单控件均有可读标签；键盘可完整操作；焦点可见

### 4.3 工程与交付

- ☐ 便携版在**未安装 Python/Node**的 Windows 上双击可用
- ☐ 数据库由 Alembic 管理；不存在 `create_all` 直改结构
- ☐ 事件流水可追溯到操作者；审计日志覆盖登录与全部写操作
- ☐ 三份医学依据可在软件内检索，结果显示出处
- ☐ `mapping.md` 中每条临床规则均可追到代码位置与测试
- ☐ `UI.md`、`_SPEC`、`mapping.md` 与实际实现一致

## 五、风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| PyInstaller 对 Python 3.14 支持不足 | 打包路线受阻 | M1 实测；失败则项目内改用 3.13 虚拟环境（不动全局） |
| 《规则映射表 v0.4》《原交接稿》缺失 | 历史规则无法逐条溯源 | 以三份原文 + 锁定稿为准，记为已知缺口（`06` V1.0-Q-02） |
| 临床规则理解偏差 | 错误的临床分支 | 所有分支必须能追溯到锁定稿章节与规则 ID；3 病例 + 红线回归测试强约束 |
| 单机 SQLite 并发限制 | 多医生同时写入冲突 | 本版本明确单机/单 worker；并发需求出现时评估迁移 PostgreSQL |
| 本地登录被误当安全方案 | 合规风险 | 在 `07` 与界面说明中明确"可追溯性，非安全边界" |
| 依据材料为扫描件 | 检索不可用 | 已实测三份均为文本型；导入脚本对扫描件给出明确提示 |
| 范围膨胀 | 交付延期 | 任何新增需求先入 `06` 并评估，不在里程碑内夹带 |
