# v0.4 数据、接口和迁移约束

2026-10-19｜项目维护者已批准完整方案（R01—R15、默认表、药物目录及清理范围）。先约束后代码。



### 3.1 技术栈

继续FastAPI、Pydantic、SQLAlchemy、Alembic、SQLite、React、TypeScript与Vite。Python使用backend/.venv和uv；所有注释与主要错误提示采用中文。没有更换数据库、引入分布式架构或重写认证的必要。

### 3.2 新旧数据的组织

| 数据 | v0.4建议结构 | 旧数据兼容方式 |
| --- | --- | --- |
| 病程 | 可空年、月，记录日及来源 | 没有则保持未知，不从旧诊断文本猜数值 |
| 检查 | 多条结构化记录，数值/摘要、单位、日期、来源、可靠性 | 从明确旧快照投影或读取；来源原文保留 |
| 测量 | 独立记录、原日期、来源、有效性与补正关联 | 不覆盖历史event.payload；未知测量日标明未记录 |
| 药物 | 可引用的方案版本、完整核对记录，目的列表、开始时间精度、实际停用日；候选目录独立维护 | 旧单用途、手输名称和完整日期可读；笼统器官获益不擅自细分，目录不覆盖旧药名 |
| 计划与观察锚点 | 计划选项与实际干预日期分离 | 原实际锚点不改成计划，不凭新选项自动补日期 |
| 历史和更正 | 原事件不改，新增详情视图与补正关联 | 旧缺字段显示未记录，旧结论及版本保持 |

具体表名与DTO在SPEC阶段确定，采用单一来源和清楚的引用关系；不为了每个页面复制一套资料。新增记录、当前患者快照、事件与审计同事务写入，保留expected_revision和request_id。

### 3.3 迁移与回退

1. 先在隔离新库及合成的旧结构副本上验证，不读取V1.0运行库；云端实际升级前再由维护流程对当前demo库做一致性备份。
2. 使用Alembic添加结构，不删旧迁移、不丢弃旧表或事件payload、不以重建库替代升级。
3. 对能确定的数据进行可追踪转换；有歧义的用途、日期、状态保留原值和待核对标识。
4. 核对迁移前后账号、病例、事件、归档及归属数量，核对典型旧记录和新记录都能打开。重复执行不重复导入历史测量或检查。
5. 保留原密钥，验证登录及会话行为。迁移不自动创建管理员或测试病例。
6. 回退以匹配的旧代码、迁移前备份和原密钥为基础；不假定把旧代码直接指向升级库就一定可用。首次运行升级需维护窗口和备份确认，未来部署说明中列明。

### 3.4 临床与安全门禁

日期不合格、信息未知、实际停药不成立时不能借默认值进入观察或确认缓解。E4客观核对与医生确认仍分两步，依据或日期更改必须重新核对。多指标录入不扩大缓解判定指标范围。获益用药不自动结束既往缓解，停药计划不自动成为执行事实。

新详情、资料聚合、测量引用和补正接口保持归属权限；归档只读。旧闭合入口不会因为新增路径被宽泛放开。默认答案、继承资料和已确认事实不在数据层混为一谈。


## 结构与接口

- Alembic新增d04data001，保留所有旧表、旧列和旧payload。新增clinical_records表：patient_id、operator_id、source_event_id、kind、clinical_date、data(JSON)、supersedes_id、created_at。kind限measurement/examination/medication_regimen/duration/correction；记录只增不改。方案/检查/测量以记录ID引用，事件payload保存本次快照及source引用。
- 现有clinical-v03路径继续提供服务；请求增加input_schema_version、测量引用/新日期、方案来源ID、方案完整性、检查列表及引用、病程年/月。老DTO输入保持兼容；v0.4新请求执行新规则。expected_revision/request_id始终必需。
- GET /patients/{id}/clinical-v04/context只读聚合；GET /patients/{id}/clinical-v04/events/{event_id}核对所属病例。GET records提供记录历史。POST corrections新增补正；明确目标record_id、reason、replacement，核对修订号与归属、归档。旧payload从不重写。
- 沿用测量必须引用本病例有效measurement记录，快照保存原测量日期；首次E2启动缺体重/确认身高阻断。E1和非启动结论可空；不把缺省字段补为新测量。
- 用药方案引用最新版本防止并发覆盖。最新完整空方案表示无药；旧空方案无完整性标记视为未知，不能向前搜非空方案。已保存卡不能被直接删除；误录通过补正，停用有实际日期。方案未变仅引用，不重复制造记录。
- 检查独立结构化保存；E4只允许HbA1c/FPG/CGM估算HbA1c进入既定判定器，其他检查仅资料。已保存检查引用验证病例、日期与修订；旧检查和摘要兼容读取。
- 旧事件不批量回写。迁移仅将可确知旧快照幂等投影到记录，保存source_event_id、日期性质、旧来源/用途。未知不猜。数据库升级前SQLite backup API一致性备份并integrity_check，备份失败阻断。回退恢复匹配旧代码、原库备份、原密钥，保留升级库副本。
- 所有新记录、临床事件、患者快照、审计在同一事务；资料补正提升clinical_revision并撤销E4旧快照资格，归档只读。读取、补正不是新的临床节点，不伪造临床决定。

## 兼容写入补充

旧输入结构仍可用于尚未写入v0.4的旧病例，并在同事务追加明确字段的资料投影，避免聚合资料陈旧；没有单独测量日则保留未知。病例已有v0.4写入后拒绝旧标签页的旧输入写入，提示刷新，以免绕过方案版本、B09和完整性门禁；旧记录读取不受影响。临床契约仍v0.3，不改变医学转移。

当前表单草稿绑定初始化修订号，不能自动采用外部更新后的版本号提交旧资料。外部补正后保留草稿并阻断保存，提供明确的重新载入动作；自己的同次E4客观核对返回的新修订号可继续用于独立确认。
