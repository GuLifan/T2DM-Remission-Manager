## 一、先看结论：要动的是这 6 件事

| # | 要改什么 | 现状 | 改后 |

| 1 | **页面主标题层级** | 工作页面最大字号 16px，24px 的标题层级从未使用 | 恢复"页面主标题"层级，且**每页只有一处** |

## 二、调研：成熟设计体系是怎么做的

（全部为 2026-09-21 实际抓取的公开文档，出处见表末）

| 体系 | 关键做法（原文要点） | 对本项目的启示 |
| --- | --- | --- |
| **GOV.UK 设计系统** | 字号阶梯（大屏）：`48 / 36 / 27 / 24 / 19 / 16`；其中 **正文 = 19px（行高 25）**、小节标题 19px、页面主标题 36px、次级标题 24px | **层级靠"字号差距"建立**（36 vs 24 vs 19），而不是靠加边框；正文比我们现在的 14px 大 |
| **GOV.UK**（表单模式） | "**one thing per page**"（一页只问一件事）；提示文字应**单句、简短**；复杂问题用陈述式标题 | 我们的阶段复评页三屏以上，直接违反该原则 |
| **NHS 设计系统** | 正文：桌面 **19px**、移动 16px；页面头部信息集中 | 临床场景的可读性优先于信息密度 |
| **IBM Carbon** | 区分 **productive / expressive** 两套类型集，理由原文是"productive … maintain **focus on tasks**"（用紧凑排版**保持对任务的专注**）；间距基于 **2x 网格**（8px 基准） | 排版的服务目标是"专注任务"；间距要有基准网格与层级 |
| **Material 3** | 15 个类型角色：`display / headline / title / body / label` × `large / medium / small`；`label` 专用于控件标签 | 控件标签与正文**是不同的角色**，我们目前两者都是 14px |
| **Nielsen 启发式** | #1 系统状态可见性、#6 识别优于回忆、#8 美学与极简设计 | 焦点与完成度反馈不是"美化"，是可用性要求 |

**对照我们的现状**（`_SPEC/09` 第三节实测证据）：

| 维度 | 成熟做法 | 本项目现状 | 差距 |
| --- | --- | --- | --- |
| 正文 | 19px（GOV.UK/NHS） | 14px | 偏小 |
| 页面主标题 | 36px（GOV.UK） | 16px（工作页面） | **几乎无层级** |
| 标题/正文比 | 36 : 19 ≈ 1.9 | 16 : 14 ≈ 1.14 | 层级不可见 |
| 间距 | 8px 基准 + 多级 | 单一 24px | 分组感缺失 |
| 信息分层 | 明确（任务/内容/辅助） | 无 | 决策与参考同权 |

> 计划作为 `UI.md` 第一部分的新增章节（编号续在"第 6 节 Token 使用率自查机制"之后，

````markdown
## 7. 信息层级与视觉焦点（强制）

### 7.1 为什么必须定这一节

规范只定义 Token 与组件、不定信息层级时，实现方只能"把所有字段都摆出来"，
结果是每个区块权重相同、页面没有落点，医生必须逐块读完才知道该做什么。
本节定义**什么内容必须比什么内容更醒目**，它是本文件其余部分的判断依据。

### 7.2 三级信息层级

每个页面只允许存在三级内容，且**同一层级内的视觉处理必须一致**：

| 层级 | 内容 | 视觉处理 | 硬性约束 |
| --- | --- | --- | --- |
| **一级｜当前任务与结论** | 本次要做的决定；系统核对结论 | 页面最大字号；唯一的强调容器；必要时用浅色容器承托 | **每页只允许一个**；不得与其他层级同权 |
| **二级｜决策区** | 需要医生填写/选择的内容 | 标准卡片 + 必填标记 + 完成度反馈 | 非当前分支的字段默认收起 |
| **三级｜参考信息** | 既往记录、时间锚点、系统说明、事件流水 | 降级处理：灰底 / 折叠区 / 侧边抽屉 | **不得使用白卡 + 描边**（避免与二级同权） |

### 7.3 页面结构（自上而下，顺序不得颠倒）

```txt
页头（患者横幅：姓名 · 性别 · 病历号 · 当前环节）
└─ 一级：任务面板 TaskPanel（"本次要做什么" + 本次结论）
   └─ 二级：决策区（分组卡片；必填标记；完成度提示）
      └─ 三级：参考信息（默认折叠：时间锚点 / 既往记录 / 事件流水）
```

### 7.4 字号层级（强制）

| 角色 | Token | 字号 / 行高 | 使用位置 |
| --- | --- | --- | --- |
| 页面主标题 | `--etmms-text-page-title` | **24px / 32px**（字重 500） | 页头标题，**每页唯一** |
| 任务标题 | `--etmms-text-task-title`（新增） | **18px / 26px**（字重 600） | TaskPanel 内，说明"现在做什么" |
| 小节标题 | `--etmms-text-section-title` | 16px / 24px（字重 500） | 决策区分组标题 |
| 正文 | `--etmms-text-body` | 14px / 20px | 内容与控件 |
| 控件标签 | `--etmms-text-label` | 14px / 20px（字重 500） | 表单标签、按钮 |
| 辅助说明 | `--etmms-text-caption` | 12px / 16px | 提示、说明（单句、不加句号） |

**约束**：

1. 页面主标题与小节标题**不得使用同一字号**（这是本文件历史上犯过的错）。
2. 同一屏内**只允许一处**使用任务标题级别及以上的字号。
3. 关键结论（一级）使用任务标题字号 + 字重 600；不得用大面积色块代替字号层级。

### 7.5 间距层级（强制）

| 用途 | Token | 值 |
| --- | --- | --- |
| 大分组之间（一级 / 二级 / 三级 之间） | `--etmms-space-6` | 32px |
| 卡片内部区块之间 | `--etmms-space-5` | 24px |
| 表单字段之间 | `--etmms-space-4` | 16px |
| 相关控件之间（标签与说明等） | `--etmms-space-2` | 8px |

**约束**：**一级与二级之间必须比二级内部更大**，否则分组感消失（现状是全站 24px）。

### 7.6 颜色语义收敛（强制）

| 颜色 | 唯一用途 | 禁止用途 |
| --- | --- | --- |
| 品牌蓝 `--etmms-primary` | 主行动按钮、可点击链接、当前选中项、焦点环 | 不得用于中性信息容器底色；不得同时多处强调 |
| 绿色（success 组） | **仅**表示"达标 / 完成 / 已缓解"等临床或流程上的**肯定结论** | 不得用于"已到某日期""信息提示"等中性状态 |
| 黄色（warning 组） | 暂缓、需注意、需要医生判断 | 不得用于装饰 |
| 红色（error 组） | 风险、阻断、不可逆操作 | — |
| 灰（surface 组） | 三级参考信息、只读区块 | 不得用于二级决策区 |

**约束**：**同一屏内使用语义色的元素不超过 2 处**；超出说明层级设计失败。

### 7.7 完成度与必填反馈（强制）

1. 必填字段必须带标记，且标记方式全站统一。
2. 决策区顶部显示完成度（如"还需填写 2 项"）；全部完成时给出肯定反馈。
3. 提交前必须展示"本次记录摘要"供医生核对（对应 GOV.UK 的 Check your answers 模式）。
4. 不可逆操作（结束主动管理、关闭路径、确认缓解、记录重新用药）**必须二次确认**，确认文案写明后果。

### 7.8 本节对应的反模式（追加到第 5 节清单）

15. ❌ **禁止**在同一页面出现两个及以上同等字号的标题（层级必须可辨）。
16. ❌ **禁止**把三级参考信息渲染成白卡 + 描边（必须降级）。
17. ❌ **禁止**用颜色代替层级（靠加颜色块而不是字号/位置来表达重点）。
18. ❌ **禁止**在同一屏使用超过 2 处语义色。
19. ❌ **禁止**在无当前任务提示的情况下直接展示长表单。
20. ❌ **禁止**缺少完成度反馈就让医生提交长表单。
````

## 五、需要你决定（这几项会改变方案的形态）

**D1｜正文字号要不要加大？**

| 选项 | 正文 | 影响 |
| --- | --- | --- |
| A（保守） | 保持 14px，只做层级与焦点 | 改动小；但与 GOV.UK/NHS 的 19px 仍有差距 |
| **B（推荐）** | 正文提到 **16px**，辅助说明 13px | 可读性明显改善，接近 Carbon 的 productive 集；需重跑全部布局核对 |
| C（激进） | 正文 19px（GOV.UK/NHS 标准） | 最好读，但一屏信息量下降约 30%，长表单会更长 |

**D2｜页面主标题用多大？** A：24px（与现有 Token 一致，我倾向）；B：32px（GOV.UK 的 heading-l）。

**D3｜一级"任务面板"是否常驻？**
A：常驻在内容区顶部（推荐，医生每次都能看到"现在做什么"）；B：只在页面首次进入或状态变化时出现。

**D4｜事件流水怎么降级？** A：折叠区（默认收起）；B：侧边抽屉；C：底部时间线（视觉降级但不折叠）。

**D5｜"必填"是硬约束还是提示？** A：只做视觉标记，服务端仍然全部可空（当前行为）；B：前端阻止提交 + 服务端校验（更严格，但要同步后端与测试）。
