# ETMMS 0.4.3 使用说明

## 账号和病例

管理员发放一次性邀请码，医生注册后病例列表为空。医生管理自己的病例；管理员按既有权限管理账号和病例。停用账号使已有会话失效，历史保留。同浏览器不同标签共享登录；同时使用两个账号请用独立浏览器会话。

在患者工作台点击“新建患者”，填写姓名、性别、出生年月和科室，再保存并开始预评估。系统生成ETMMS病例编号，不预填临床事实。列表支持搜索、排序和已归档病例查看。

## 日期

普通医生使用系统日期，工作台日期只读。管理员在患者列表或病例页左上点击“调整日期”，可设置自己的业务日或恢复系统日；账号管理区也保留入口。它不改变服务器时间或其他医生日期。

日期变化后，旧页面须载入最新日期再核对，不能提交旧日期草稿。检查、测量、实际停药按发生日期填写；既往资料可以记录，未来已发生事实会被拒绝。下次复评是计划，可以在未来。

## 管理流程

1. **预评估**：核对入口事实和治疗背景，由医生决定进入完整评估、暂缓或当前不启动。测量可选；病程年、月独立可空，填年时月0—11，只填月时允许18个月，全空表示未知。
2. **完整评估**：填写诊断依据、可靠检查或近期血糖、用药及管理约束。首次启动需基线体重和确认身高；医生确定意愿、阶段、主要目标、干预和复评安排。页面默认不等于已经确认。
3. **阶段复评**：沿用原测量或新增体重和日期；上一完整药物方案带入，主要记录变化。常用药物按类别多选添加，也可手输。目录不推断剂量、降糖作用或目的。
4. **观察**：计划停药与实际停药分开。核对全部相关药物实际状态、完整停药日、当前用药和适用干预日期，满足条件后进入观察。资料缺失或尚未到期时按任务处理。
5. **缓解判定**：显式选择可靠且日期合格的判定检查，先客观核对，再由医生独立确认。显示本轮最早判定日—当前业务日；范围前的检查可以保留历史，不能据此确认本轮缓解。客观符合不自动形成缓解结论。
6. **缓解后复评**：核对血糖、用药和风险，记录维持、风险上升、不可评价、终止或待复核。获益用药不自动抹除既往缓解历史；相关返回处理仍须完整核对当前方案及用途。

## 药物卡片

展开卡片可编辑或“从本次方案移除”，保存新方案时历史保留。移除后需重新勾选完整核对；全部移除还须确认本次当前无药。返回核对、取消或未保存均不提交变化。

**移除不代表已经实际停药。** 它不生成停药日期或观察计时。若本次记录实际全部停药，保留相关药物卡，逐药核对停用状态和日期；之后再从当前方案移除。未知空列表不能当作无药。历史汇总有矛盾时按提示明确核对，不自动改写历史。

用药目的可多选；开始时间保留年、年月、完整日或未知精度。仅知道年月时不补造某日。

## 提示、草稿和并发

提交遗漏、错误及未通过核对结果居中显示。可返回修改，或点击定位按钮回到相关字段，已填草稿保留。E4需要补充的原因保存后仍可查看，关闭后可在底部再次打开。

修改相关事实会撤销旧客观核对资格。遇到病例已更新提示，核对草稿后明确载入最新资料；只有执行该操作才放弃本页草稿。不要反复点击重复提交。身份或日期变化须重新核对。

## 历史、补正与归档

本次管理记录可展开检查、用药、测量及医生决定。资料记录与补正保留原值、前后差异、原因、操作者和时间，不改写原临床结论。原测量日、历史来源和业务日/真实记录时间分别展示；来源兼容显示不改变原存储事实。

“归档并新建”使旧病例只读并保留历史，复制基本资料开启新管理记录；旧检查、用药、测量和结论不自动带入。小屏用“展开管理路径”导航；日期、补正及确认窗口支持取消或Escape。

## 医学依据和维护

完整配置并导入依据后可检索原文及页码/章节，并在登录后下载原件。系统负责计算和提醒，医学决定由医生作出。

现有环境维护按[完整替换指南](DEPLOY_SEALOS.md)保留数据与配置。工程根执行`bash start.sh`、`bash start.sh status`、`bash start.sh stop`。Devbox重启后手工启动，不重新初始化管理员。
